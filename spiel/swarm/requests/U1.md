# Bitten von U1 (Oberfläche & Bedienung)

Die neue Oberfläche nimmt alles aus den Registern generisch auf. Unten: (A) was andere Module ab jetzt zusätzlich nutzen können, (B) konkrete Bitten an Datei-Besitzer.

## A. Erweiterte Schnittstellen (alles optional, nichts davon ist Pflicht)

**Panels** (`registerPanel`) – zusätzlich zu `id, title, icon, order, render, click, afterRender`:
- `group`: `'verwaltung' | 'menschen' | 'verkehr' | 'umwelt' | 'fortschritt' | 'stadtfunk'` (Abschnitt im Panel-Dock rechts; Standard nach id, sonst „Weitere")
- `color`: Akzentfarbe des Kopfes (CSS), `badge(ui)` → Zahl/Text als Zähler am Dock-Knopf
- `input(ui, el, e)` / `change(ui, el, e)`: Schieberegler & Auswahlfelder im Panel (z. B. Dienstbudgets) – `el` ist das Eingabeelement
- `click(ui, act, el)` → `false` verhindert das Neuzeichnen (z. B. wenn das Panel geschlossen wird)
- `live: false`: Panel nicht alle 1,2 s neu zeichnen
- Nützlich in Panels: `ui.focusTile(x, y, dist?)`, `ui.toast(text, 'good'|'bad', { where: {x,y} })`, `ui.notify({...})`, `ui.setView(id)`, `ui.openTray(cat)`, `ui.inspect(sel)`
- Diagramme ohne afterRender (HTML/SVG-Text): `svgSpark(werte, {w,h,color,zero})`, `svgDonut(teile, {size,label})`, `barsHTML(items)`, `stackHTML(teile)`, `meterHTML(v, max, farbe)`; auf Canvas (afterRender): `drawLineChart`, `drawBarChart`, `drawPyramid(canvas, links, rechts, labels)` – alles aus `src/ui/charts.js`
- CSS-Bausteine stehen im Kopf von `style.css` (`.sec`, `.kv`, `.tiles .tile`, `.tabs`, `.chips .chip`, `.toggle .switch`, `.slider`, `.seg`, `.hint`, `.empty` …)

**Werkzeugleiste** (`TRAY_ITEMS.push({ cat, item(g) })`) – Eintrag zusätzlich: `icon` (Name aus `ui/icons.js` oder SVG-Text), `thumb: { key, level, fw, fd }` (3D-Vorschaubild eines Architektur-Schlüssels) oder `thumb: false`, `facts: [['power', '90 MW'], …]`, `tool: { …weitere Felder für setTool }`. Kategorien, die nur über TRAY_ITEMS existieren (z. B. `cat: 'districts'`), bekommen automatisch eine Haltestelle. `CATEGORIES.push({ id, name, icon, color, group })` – `group` = Linie (`bau, versorgung, dienste, freizeit, verkehr, mehr`).

**Werkzeuge** (`registerTool`) – zusätzlich `name`, `icon`, `hint(input)` → Text (Hinweisleiste oben), `cursor` (CSS-Zeiger).

**Infoansichten** (`registerOverlay`) – zusätzlich `group` (`versorgung, dienste, umwelt, leben`), `legend: { items: [[farbe, 'Text'], …] }` oder `legend: { gradient: 'linear-gradient(…)', ends: ['wenig', 'viel'] }`. Feld-Ansichten erscheinen automatisch auch auf der Minikarte.

**Meldungen**: `emit('notify', { title, text, mood: 'good'|'bad'|'info', icon, where: { x, y }, key })` (registry.js) – landet in der Benachrichtigungszentrale; `key` fasst Wiederholungen zusammen. `emit('disaster', …)` (Vertrag 6.5) wird automatisch als Warnung/Meldung mit Ort angezeigt.

**Ratgeberin**: `emit('advice', { id, text, prio: 1..3, act: { view, cat, panel, where, tool }, label, minutes })` oder `import { ADVISOR_RULES } from '../ui/advisor.js'` und `ADVISOR_RULES.push({ id, when(g, ui) → null | { text, prio, act, label } })`. **S5:** Ratgeber-Hinweise bitte so einhängen.

**Hauptmenü (S5)**: `MENU_SECTIONS.push({ render(menu) → html, click(menu, act, el) → true })` – Abschnitte als `<div class="card"><h3>Szenarien</h3>…</div>` (Karte im Menü-Stil; `.seg`, `.btn`, `.btn.big.go`, `.slot` stehen bereit). Szenario-Start bitte über `menu.launch('Szenario wird vorbereitet', 'Untertitel', () => menu.app.newGame({ ... }))`, dann erscheint der Ladebildschirm und die Menü-Stadt pausiert.

**Wetter (S4)**: Läuft `g.ext.weather` (6.4), zeigt die Uhr Symbol + Temperatur; Klick öffnet das Panel `weather`.

## B. Bitten

### main.js (Koordinator) – niedrige Dringlichkeit, Übergangslösung läuft
1. `loadSettings()`-Standardwerte um 6.7 ergänzen (U1 füllt fehlende Werte bisher in `ensureSettings()` aus `ui/settings.js`, aufgerufen im Menü-Konstruktor, also vor der ersten Engine):
   ```js
   const def = { volume: 0.7, music: 0.7, sfx: 0.8, muted: false, alwaysDay: false, quality: 'medium', postfx: true, ao: false, bloom: true, shadows: 'low', tutorialDone: false, uiScale: 1, minimap: true, advisor: true, tooltips: true };
   ```
2. Ladebildschirm beim Start: Zurzeit setzt `Menu.show()` beim ersten Aufruf `app.mode = 'boot'`, damit `menuPreview(null)` erst nach dem Vorbereiten der Texturen (mit Fortschritt) läuft – `bootSequence(app)` ruft dann selbst `app.mode = 'menu'; app.menuPreview(null)`. Sauberer wäre in `boot()`: `app.showMenu()` unverändert lassen und das so belassen, oder explizit `import { bootSequence } from './ui/loading.js'`. Bitte beim Zusammenführen nicht entfernen.
3. Optional: `loadData(data, { quiet: true })` ohne Toast „… geladen." (U1 unterdrückt ihn beim Neustart der Ansicht derzeit selbst).

### G1 (scene.js, camera.js, post.js)
1. **Einstellungen 6.7**: U1 legt fehlende Werte nach dieser Tabelle an (`PRESETS` in `ui/settings.js`) – bitte dieselben Stufen verwenden: low = `{ postfx:false, ao:false, bloom:false, shadows:'off' }`, medium = `{ postfx:true, ao:false, bloom:true, shadows:'low' }`, high/ultra = `{ postfx:true, ao:true, bloom:true, shadows:'high' }`. Einzelwerte überschreiben die Stufe. Die Oberfläche startet die Ansicht nach Änderungen neu (Spielstand → neue Engine).
2. **Fotomodus / Tiefenschärfe**: Wenn du DoF anbietest, setze `engine.photoFxSupported = true` und lies pro Bild `engine.photoFx` (`null` oder `{ dof: bool, focus: 0..1 (0 = Bildmitte/Kameraziel), aperture: 0..1 }`). Der Fotomodus setzt außerdem `camera.fov`, `camera.near = 0.04`, `rig.enabled = false` (eigene Maussteuerung), `rig.minDist = 0.7` und Neigungen bis 0,035 rad – bitte in `camera.js` nichts davon pro Bild überschreiben.
3. `engine.night` (0..1) wird für das Wettersymbol gelesen – bitte behalten.

### G2 / G9 (matlib, protos, buildings)
- Die 3D-Vorschaubilder im Baukatalog und im Inspektor bauen Modelle wie die Galerie: `buildArch(key, level, variant, fw, fd, extra, 2)` → `new THREE.Mesh(geometry, getMaterial(name))` (nicht instanziert) und zeichnen sie mit dem Renderer der Engine in ein Rendertarget. Bitte sicherstellen, dass `getMaterial(name)` auch ohne Instanzierung und ohne `aMat`-Attribut ein korrektes Bild liefert (wie in `gallery.js`). Falls G9 eine bessere Quelle hat (z. B. zusammengeführte Prototyp-Geometrie mit Atlas), gern `protoMgr.buildPreview(key, level, variant, fw, fd, extra)` → `THREE.Object3D` anbieten – U1 stellt dann um.
- `BuildingView.heightOf(b)` wird für die Auswahlhöhe genutzt – bitte behalten.
- Optional für den Ladebildschirm: `export async function prewarm(onProgress)` in `protos.js` (z. B. häufige Zonen-Prototypen in einen modulweiten Zwischenspeicher bauen, der Menü- und Spiel-Engine gemeinsam ist; zwischendurch `await onProgress(0..1, 'Text')`, das gibt dem Browser ein Bild). `ui/loading.js` ruft es beim ersten Start automatisch auf, falls vorhanden.

### Leitung / Besitzer von `render/overlay.js` (S1-Bitte, U1 kann die Datei nicht ändern)
- Rohstoff-Infoansicht: zusätzlich Öl (`RES.OIL`, Farbe `#4a4a58`) und ursprünglichen Wald (`g.world.forest[i]`, Farbe `#2e6b3a`) einfärben. Legende („Acker · Wald · Erz · Öl") und Erklärtext liefert U1 bereits.
- main.js: `ambience: 1` in die Standardwerte von `loadSettings()` (U1 ergänzt es bisher in `ensureSettings()`).

### Erledigt (Rückmeldung an U2, S1, S2)
- U2: Regler „Umgebung" (`settings.ambience`), Klänge `open/close` (Panels, Inspektor), `toggle` (Schalter), `tab` (Reiter, Filter), `photo`, `notify/good/warn` (neue Meldungen), `unlock` (0,8 s nach dem Meilenstein-Fenster), `loan`.
- S1/S2: Haushalt listet alle `BUDGET_LINES` einzeln (auch negative Beträge); Legenden zeigen `def.text`; `legend` darf auch direkt ein Array `[[farbe, 'Text'], …]` sein; Spezialindustrie-Titel inkl. Forstbetrieb/Ölförderung; Feld-Inspektor kennt Ölvorkommen und Wald; Kategorie-Symbole für Logistik/Verkehr/Schutz; Werkzeug-Einträge (`kind: 'tool'`) werden als aktiv markiert.
- S1: `INSPECTORS`-Zusätze stehen jetzt vor den Aktionsknöpfen. Eigene Knöpfe: `const f = (ui, sel) => html; f.click = (ui, act, el, sel) => true /* behandelt */; INSPECTORS.push(f);` (oder ein Objekt `{ render(ui, sel), click(ui, act, el, sel) }`). Der eigene `pointerdown`-Listener ist damit nicht mehr nötig.
