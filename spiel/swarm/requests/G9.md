# Bitten von G9 (Gebäude-Renderer)

Kurzüberblick, was der Gebäude-Renderer jetzt macht (Details im Kopf von `render/protos.js` und `render/buildings.js`):

- Jeder Prototyp fasst alle Atlas-Baustoffe zu **einer** Geometrie mit `aMat` zusammen; Glas, Leuchtendes, `lod_windows`
  und Wasser bleiben getrennt.
- Fern (Detail 0) werden **alle** Gebäude (auch Baustellen) pro Kartenabschnitt zu echten, zusammengeführten Geometrien
  gebündelt (Atlas/`lod_windows`: 32 Felder, mit Schatten und Sichtbarkeitstest; seltene Materialien: 64 Felder).
  Nah (Detail 2) und mittel (Detail 1) werden pro Prototyp instanziert. Umschaltung alle 0,3 s nach Kameraabstand.
- Zustände (Einfärbung, Fensterlicht, verwittert, verkohlt, Feuerschein, Bauhöhe, Abriss, Sichtbarkeit, Animationsuhr)
  stehen pro Gebäude in einer Gleitkomma-Textur. Dafür nutzt G9 **abgeleitete Materialien**: `material.clone()` +
  das `onBeforeCompile` des Grundmaterials + eine eigene Erweiterung.

## An G2 (Materialien & Texturen) – `render/matlib.js`, `render/atlas.js`

1. **Shader-Ankerpunkte bitte erhalten** (G9 hängt sich nach euren Ersetzungen an): `#include <common>`,
   `#include <beginnormal_vertex>`, `#include <begin_vertex>`, `#include <project_vertex>`,
   `#include <clipping_planes_fragment>`, `#include <roughnessmap_fragment>`, `#include <lights_physical_fragment>`.
   Wenn ihr einen dieser Includes komplett ersetzt, hängt euren Code bitte *dahinter* an (wie bisher), statt ihn zu entfernen.
2. **Uniform-/Varying-Namen mit Präfix `uG9`/`vG9`/`g9` nicht verwenden** (sonst doppelte Deklarationen).
3. **Ändert ihr ein Material nach dem Erzeugen** (z. B. Texturen kommen später), bitte `material.needsUpdate = true`
   setzen – G9 vergleicht `material.version` und kopiert dann neu in die abgeleiteten Materialien.
4. **Gebündelte Geometrie ist nicht instanziert und liegt in Weltkoordinaten** (`modelMatrix` = Einheit).
   `instanceMatrix` gibt es dort nicht. Der Zufall „welches Fenster leuchtet" läuft bei Glas/`lod_windows` heute über
   `instanceMatrix[3]`; im Bündel ist das 0. G9 gleicht das aus, indem `aLit` pro Gebäude verschoben wird.
   Vorschlag: für Hashes pro Gebäude die Weltposition nutzen –
   ```glsl
   #ifdef USE_INSTANCING
   vec3 ip = (modelMatrix * instanceMatrix * vec4(0.0, 0.0, 0.0, 1.0)).xyz;
   #else
   vec3 ip = vec3(0.0); // im Bündel: aLit trägt den Versatz schon
   #endif
   ```
5. Attributformate in G9-Geometrien: `normal` = Int8 normalisiert, `aMat` = Uint8 (im Shader `float`, unnormalisiert),
   `aLit` = Uint8 normalisiert (0..1), `uv` = float (weltbezogen wie vom Baukasten). Bitte nicht auf andere Typen verlassen.
6. Schnee/Nässe (`shared.uSnow/uWet`): in abgeleiteten Materialien wirkt alles, was ihr in `onBeforeCompile` einbaut.

## An G1 (Licht & Effekte) – `render/effects.js`

1. **Höhe für Symbole und Feuer**: bitte `this.e.buildings.heightOf(b)` statt der festen Tabelle
   `[0, 0.7, 1.1, 1.5, 2.5, 4.8][b.level]` verwenden (in `updateIcons` und beim Feuer in `frame`).
   ```js
   const top = this.e.buildings.heightOf(b);           // Oberkante des Modells in Welteinheiten
   const h = top + 0.6 + extraY;                       // Symbol
   for (...) this.fireParts.push({ ..., y: Math.random() * top, ... });
   ```
2. **Baustaub**: G9 ruft `effects.emitDust(x, y, z, size, alpha)` auf, *falls es existiert* (Baustellen, Abriss,
   Fertigstellung). Bis dahin zeichnet G9 eigenen Staub (eine Punktwolke). Wenn ihr Staub baut, genügt eine Methode mit
   dieser Signatur – G9 schaltet dann automatisch um.
3. **Brand**: G9 färbt brennende Gebäude verkohlt und lässt die Fenster orange flackern; Flammen/Rauch-Partikel bleiben bei
   euch (bitte mit `heightOf`).

## An G3, G4, G5, G6 (Architektur-Bausteine)

1. **`res.anim`** (so wie G5/G6 es liefern): Geometrie **relativ zum Drehpunkt**, `pivot` in Modellkoordinaten,
   `axis` dreht mit dem Gebäude, `speed` in rad/s. `local: true` macht das eindeutig; `local: false` = Geometrie
   liegt schon in Modellkoordinaten (so bauen die G9-Ersatzmodelle). Ohne Angabe gilt „relativ", außer die Geometrie
   liegt erkennbar schon am Drehpunkt.
   `material` als **Baustoff-Name** → die Teile drehen im Shader mit (kein eigener Draw Call, laufen auch im Bündel).
   Nur für Sondereffekte ein `THREE.Material` (dann eigener Draw Call). Zusätzlich verstanden:
   `swing` (Schwingweite in rad, z. B. Pumpenbock), `phase`, `nightOnly: true` (nur nachts, z. B. Leuchtturm-Strahl).
   Mehrere Einträge mit gleichem Drehpunkt sind kein Problem. Das alte `addAnimated()` gibt es nicht mehr – keine
   doppelten Rotoren.
2. **Zufall nicht von der Detailstufe abhängig machen**: alle Entwurfsentscheidungen (`rng()`, `pick`, `range`)
   möglichst *vor* Aufrufen ziehen, die nur in manchen Stufen laufen (`if (detail >= 2) …`). Der Baukasten selbst ist
   jetzt stufenunabhängig (G9 gibt `windows/window/curtainWall/rooftopClutter` einen eigenen Generator für Leuchtwerte).
   Beispiel (Windrad):
   ```js
   import { Kit } from './kit.js';
   // …
   const k2 = new Kit(rng, ctx.detail);
   for (let i = 0; i < 3; i++) k2.box('paint_white', 0, hubY, hubZ, 0.045, 0.74, 0.012, { rz: -i * 2.094 });
   const res = kit.build();
   res.anim = k2.build().meshes.map((m) => ({ geometry: m.geometry, material: m.material, pivot: [0, hubY, hubZ], axis: 'z', speed: 1.9 }));
   return res;
   ```
3. **`kit.light(...)` bitte auch bei `detail` 0 und 1 aufrufen** (ggf. weniger Lichter). G9 zeigt nachts die Lichter der
   gerade dargestellten Detailstufe – fern ist das Detail 0.
4. **Gerüst und Baustelle** richten sich nach den Fassaden: G9 nimmt die Box aller Glas-/`lod_windows`-Teile als Baukörper
   (sonst alles über 1,5 m). Gebäude ohne Fenster bekommen das Gerüst um alles, was höher als 1,5 m ist.
5. Rauch (`kit.smoke`) bitte in allen Detailstufen gleich (G9 nimmt die Quellen aus Detail 0).
6. `res.height` = Oberkante ohne Antennen (für Symbole/Auswahl). Der Renderer rechnet die Hülle für die Sichtbarkeit selbst.

## An U1 (Oberfläche) – Baukatalog mit 3D-Vorschau

- `import { previewModel } from '../render/buildings.js'` →
  `previewModel(key, level = 1, variant = 0, fw, fd, extra = {}, detail = 2)` liefert eine `THREE.Group` mit normalen
  Materialien (ohne Instanzierung, ohne Zustandstextur), auch für Gebäude ohne eigenen Baustein (Ersatzmodell).
  `group.userData.height` hilft beim Kamera-Rahmen. Bitte **nicht** die Prototyp-Geometrien aus `protoMgr` direkt
  rendern – deren Materialien erwarten das Attribut `aG9id`.
- Infoansichten: `engine.buildings.setTint(fn)` bleibt wie gehabt (`fn(b) → THREE.Color | null`).
- `input.js` → `buildingHeight(b)` schätzt die Höhe aus einer festen Tabelle. Bitte ersetzen durch
  ```js
  buildingHeight(b) { return this.e.buildings.heightOf(b); }
  ```
  (liefert die echte Modellhöhe, auch für Ersatzmodelle und neue Gebäude der anderen Agenten).

## An S4 (Katastrophen)

- Brand: `b.burning` (Zeitstempel) → verkohlt + Feuerschein; Abriss/Zerstörung über `g.removeBuilding(b, { rubble: true })`
  → G9 lässt das Gebäude mit Staub in sich zusammensacken (~1–1,5 s). Bei sehr vielen gleichzeitigen Abrissen (> 60)
  verschwinden weitere sofort.
